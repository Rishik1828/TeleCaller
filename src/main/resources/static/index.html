📚 Architecture & Mathematical Pacing Formulation
Critical Architecture Invariant: Campaign → Pacing Engine → Safety Controller → Call Allocator → Telecom Provider
The Pacing Engine never contacts the telecom provider directly. Every single outbound call must be approved by the Safety Controller.

1. Predictive Pacing Formula

The system models future agent availability over a call setup horizon \(H\) (typically 10–20s) based on average talk duration:

Turnover Rate = H / AvgTalkDurationSeconds Expected Freed Agents = ConnectedCalls × Turnover Rate Expected Net Capacity = AvailableAgents + ExpectedFreedAgents - RingingCalls Smoothed P(Answer) = (ObservedAnswers + m × P_prior) / (TotalAttempts + m) Raw Dials Needed = Expected Net Capacity / Smoothed P(Answer) Proposed Dials = floor(Raw Dials × SafetyBufferFactor) [where Buffer = 0.85]

2. Agent & Call State Machines

Agent Lifecycle: AVAILABLE → RESERVED → DIALING → CONNECTED → WRAP_UP → AVAILABLE (Any active state → OFFLINE / PAUSED via explicit transition) Call Lifecycle: QUEUED → RESERVED → INITIATED → RINGING → ANSWERED → CONNECTED → COMPLETED (Terminal states: COMPLETED, FAILED, CANCELLED)

3. Atomic Reservation & Concurrency Guarantees

To prevent two distributed dialer workers from reserving the same agent concurrently, the system relies on database-level Compare-And-Swap (CAS) with version tracking:

UPDATE agents SET state = 'RESERVED', reservation_expires_at = :expiresAt, version = version + 1 WHERE id = :id AND state = 'AVAILABLE' AND version = :expectedVersion;
